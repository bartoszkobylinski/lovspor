lovverk is an MCP server. Your client talks either to the hosted service at https://lovspor.no/mcp, through a connector you sign in to with OAuth 2.1, or to a copy you run on your own machine, which needs nothing.

Claude Desktop and claude.ai — as a connector

The hosted service logs you in with OAuth 2.1, so there is nothing to paste. This is the procedure we have run from claude.ai:

  • Add a custom connector with the address https://lovspor.no/mcp.
  • Choose Sign in now.
  • For client registration, choose Register automatically. The default, which uses Claude's published identity, does not work with this service.
  • Log in on the page that opens. The tools answer once you are back in the chat.

The labels inside the client change more often than this page does. If one has moved, what matters is the address, OAuth as the way to log in, and automatic registration.

ChatGPT — as a connector

Also with OAuth 2.1. The procedure we have run:

  • Turn on developer mode in ChatGPT.
  • Create a connector with the address https://lovspor.no/mcp and OAuth as the authentication.
  • Log in on the page that opens.

Run it yourself

You do not have to ask anyone. Run the server yourself — it fetches the corpus down to your machine and talks to your client over stdio. In Claude Code:

uvx lovspor fetch-corpus
claude mcp add lovverk -- uvx lovspor mcp

This works today: no account, no API key. Every tool except semantic_search reads only files and git on your own machine, and semantic_search needs an embedding key you supply yourself.

Claude Desktop — a local copy

Add this to the Claude Desktop config file (claude_desktop_config.json — its location depends on your operating system) and restart the client:

{
  "mcpServers": {
    "lovverk": {
      "command": "uvx",
      "args": ["lovspor", "mcp"]
    }
  }
}

Cursor and Codex

No tested procedure. We have not run the setup in these clients ourselves, and we are not going to invent the steps.

Use a client that supports a connector with OAuth sign-in, or run the server yourself as above. If you get one of these clients working against the hosted service — or if you cannot — tell us at kontakt@lovspor.no, and it can stand here as a tested recipe with your name on it.

The engine is open source under AGPL-3.0: github.com/bartoszkobylinski/lovspor. What the tools answer is in the documentation; the state at the last release is on status.
