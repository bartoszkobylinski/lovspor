lovverk is an MCP server that lets your AI tool look up Norwegian statutes and regulations. The hosted service has one address:

https://lovspor.no/mcp

One click selects the whole address or command; copy it with Ctrl+C (⌘C on a Mac). You sign in inside the client, there is nothing to paste beyond the address, and it costs nothing.

Claude

Run from claude.ai against the hosted service on {{ fact("code.connect.claude.walked_on", kind="code") }}.

  1. Add a custom connector.
  2. Enter the address https://lovspor.no/mcp.
  3. Choose Sign in now.
  4. Under client registration, choose Register automatically.
  5. Sign in on the page that opens. Back in the conversation, the tools answer.

In Claude Desktop the same choices are what count, but we have run the steps from claude.ai only. Signing in and troubleshooting are in the full Claude guide.

ChatGPT

Run in ChatGPT against the hosted service on {{ fact("code.connect.chatgpt.walked_on", kind="code") }}.

  1. Turn on developer mode in ChatGPT.
  2. Create a connector with the address https://lovspor.no/mcp.
  3. Choose OAuth as the authentication.
  4. Sign in on the page that opens. Back in the conversation, the tools answer.

Which ChatGPT subscriptions have developer mode we have not checked, so it is not stated here. Signing in and troubleshooting are in the full ChatGPT guide.

Claude Code

Local copy, no account

The server fetches the corpus to your machine and talks to Claude Code over stdio:

uvx lovspor fetch-corpus
claude mcp add lovverk -- uvx lovspor mcp

Every tool except semantic_search then reads only files and git on your own machine. Claude Desktop as a local copy: see the Claude guide.

The hosted service

Run in Claude Code against the hosted service on {{ fact("code.connect.claude-code.walked_on", kind="code") }}.

Add the server:

claude mcp add --transport http lovverk https://lovspor.no/mcp
  1. Start Claude Code in the same project. In the session, type /mcp, choose lovverk, then Authenticate. The browser opens.
  2. Sign in with email or Google.
  3. Choose Allow access. The page warns that the redirect points to an unverified application on your machine; that application is Claude Code.
  4. The page says Authentication successful. Back in the session, the tools answer.

If the browser does not open, Claude Code shows the link to copy. If the page after Allow access shows a connection error, paste the address from the browser where Claude Code asks for it. If you already have the local copy, give this one another name, such as lovverk-hosted.

VS Code

Run in VS Code against the hosted service on {{ fact("code.connect.vscode.walked_on", kind="code") }}.

  1. Press ⌘⇧P (Ctrl+Shift+P), run MCP: Add Server and choose HTTP.
  2. Enter the address https://lovspor.no/mcp and the server ID lovverk.
  3. When VS Code asks, choose Allow, then Open to go to the sign-in page.
  4. Sign in with email or Google and choose Allow access. The page warns that the redirect points to an unverified application on your machine; that application is VS Code.
  5. Open the chat, use Agent mode and ask your question. When VS Code asks to run a lovverk tool, allow it.

Check that the answer shows a tool step. In our first attempt the chat said lovverk needed authentication and then answered anyway, without calling lovverk, and the answer looked right. If you see that message, sign in again and ask again.

Other clients

No tested procedure for Cursor and Codex. We have not run the setup in these clients ourselves, so we do not make up the steps or the configuration files.

What a client needs to use the hosted service:

  • the address https://lovspor.no/mcp;
  • the Streamable HTTP transport;
  • sign-in with OAuth, which the client starts itself.

Where this goes differs from client to client. If your client cannot sign in, you can run the server yourself, as in the local copy above.

Start here

Three questions that exercise the tools. Ask them in a new conversation; the corpus is Norwegian, so ask in Norwegian.

«Hvor lenge må jeg ha jobbet for å få sykepenger fra arbeidsgiveren?» (How long must I have worked to get sick pay from my employer?)

The answer should rest on folketrygdloven § 8-18 (the National Insurance Act) and quote it. Then ask about folketrygdloven § 8-99 — the tool should answer that the section does not exist.

«Hvor høyt må taket være i et rom for varig opphold i en bolig?» (How high must the ceiling be in a habitable room in a dwelling?)

The answer should rest on byggteknisk forskrift (TEK17) § 12-7, a regulation rather than a statute.

«Når ble arbeidsmiljøloven sist endret, og hva ble endret?» (When was the Working Environment Act last changed, and what changed?)

The answer should rest on the change history in the corpus, not on the model's memory.

Help

  • The model does not use lovverk. Ask for it in words: "Look it up in lovverk …". A model decides for itself when to call a tool.
  • Authorization failed after you have signed in. Then the fault is in the setup on our side, not yours. Write to kontakt@lovspor.no.
  • A label has moved. The labels inside the clients change more often than this page. What counts is the address and OAuth as the sign-in method.
  • The tools do not answer. The state at the last release is on status. The service always requires sign-in, so a call without it is refused.
  • What can the tools answer? See the documentation.

The engine is open source under AGPL-3.0: github.com/bartoszkobylinski/lovspor. Questions: kontakt@lovspor.no.
