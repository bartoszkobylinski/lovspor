lovverk is an MCP server. Your client talks either to the hosted service at https://lovspor.no/mcp, or to a copy you run on your own machine. The first needs a token or an OAuth 2.1 login. The second needs nothing.

Without a token

You do not have to ask anyone. Run the server yourself — it fetches the corpus down to your machine and talks to your client over stdio:

uvx lovspor fetch-corpus
claude mcp add lovverk -- uvx lovspor mcp

This works today: no account, no token, no API key. Every tool except semantic_search reads only files and git on your own machine, and semantic_search needs an embedding key you supply yourself.

Claude Code — the hosted service

This is the procedure we run ourselves, in one line:

claude mcp add --transport http lovverk \
  https://lovspor.no/mcp \
  --header "Authorization: Bearer YOUR_TOKEN"

Replace YOUR_TOKEN with the token you were given. /mcp in a fresh session shows that lovverk is registered.

Claude Desktop — a local copy

Add this to the Claude Desktop config file (claude_desktop_config.json — its location depends on your operating system) and restart the client:

{
  "mcpServers": {
    "lovverk": {
      "command": "uvx",
      "args": ["lovspor", "mcp"]
    }
  }
}

Claude Desktop and claude.ai — as a connector

The hosted service logs you in with OAuth 2.1, so there is no token to paste. This is the procedure we have run from claude.ai:

  • Add a custom connector with the address https://lovspor.no/mcp.
  • Choose Sign in now.
  • For client registration, choose Register automatically. The default, which uses Claude's published identity, does not work with this service.
  • Log in on the page that opens. The tools answer once you are back in the chat.

The labels inside the client change more often than this page does. If one has moved, what matters is the address, OAuth as the way to log in, and automatic registration.

ChatGPT — as a connector

Also with OAuth 2.1 and no token. The procedure we have run:

  • Turn on developer mode in ChatGPT.
  • Create a connector with the address https://lovspor.no/mcp and OAuth as the authentication.
  • Log in on the page that opens.

Cursor and Codex

No tested procedure. Both accept a token in a field, which is the form the service offers them. But we have not run the setup in these clients ourselves, and we are not going to invent the steps.

Use the client's own documentation, with the address https://lovspor.no/mcp and your token. If you get it working — or if you cannot — tell us, and it can stand here as a tested recipe with your name on it.

Getting a token

Private beta. One person operates the service, so tokens are handed out by hand. The connectors above log in instead and need no token.
