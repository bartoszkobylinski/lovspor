## Defect found by real bytes

`parse_sak` compared each decision's session with `sak_sesjon` and dropped the
reference on any difference. Real cases cross sessions: sak 63056 is `2014-2015`
with decisions from `2015-2016`, and sak 103533 is `2024-2025` with a decision
from `2025-2026`. Both produced a false `unresolved`. Filed as
[#755](https://github.com/bartoszkobylinski/lovspor/issues/755) and fixed in this
PR. A decision now keeps its own session. It is refused if it predates the case
or if a present `eksport_id` disagrees with the link text. The parser version
moved to `sak-xml-2`. The old unit test pinned the wrong assumption on a synthetic
fixture and now asserts the real shape.

## Measurements

- **Lovdata citation coverage, all law documents in the archive.** From 2013 on,
  1,658 of 1,663 cite exactly one `Lovvedtak` in the header and 5 cite none.
  Before 2013, 279 cite one and 1,074 cite none. No document cites two. This is a
  count of header citations, not of correct links.
- **Member naming.** 3,011 law documents follow `nl-YYYYMMDD-NNN`. 5 use
  `sf-YYYYMMDD-NNNN`. The reader accepts both and refuses two matches.
- **Stortinget caching.** Fetches from 17:26 to 17:47 UTC returned identical bytes,
  including `respons_dato_tid` 2026-11-01T18:26:31.8369978+01:00. A changed query
  string returned the same bytes too. The response therefore carries a server
  timestamp and comes from a cache.
- **Not measured.** Whether the digest changes after the cache expires. The body
  contains generation timestamps, so a future capture may differ with no change
  in substance. Compare parsed identities across captures, not digests.
- **Lovdata archive.** Two downloads on 2026-11-01 had the same digest. The archive
  can be rebuilt upstream, so the member digest is the stable reference only until
  that is measured too.
- **API sanction data.** The Stortinget XML has no law number for the act. Step
  `LOVVEDT` is dated 17.06.2022, matching the act's date, but this was not used
  as proof.

## Replay

- `tests/unit/test_legislative_chain.py` runs on every CI build. It reads the four
  committed Stortinget responses, checks their digests, and covers the negative
  cases. Its Lovdata documents are synthetic, because raw Lovdata XML is never
  committed.
- `tests/integration/test_pilot_e4_replay.py` replays all eight recorded verdicts
  from the real archive with no network. It runs only where the gitignored cache
  exists and **skips in CI**. A skip there is not a Lovdata replay. It passed
  locally on 2026-11-01.
- To rebuild the cache and the evidence file:

```bash
uv run python scripts/pilot_e4.py --evidence docs/research/data/pilot-e4-evidence-2026-11-01.json --lovverk-commit "$(git -C ../lovverk rev-parse HEAD)" --research-commit "$(git rev-parse origin/main)"
```

This rewrites timestamps, and it changes digests if upstream bytes changed.

## Unproven

- One act proves one act. No recall, no rate, no generalised join.
- A digest proves which bytes this run read. It does not authenticate origin beyond
  TLS to the official host, and no source signs its responses.
- Nothing here says who wrote a provision, how a § was voted, or when anything took
  legal effect.
- Lovtidend avd. I was not previously an ingested dataset. It was read for this
  pilot only.

## Owner decisions needed before publication

1. **Artifact location:** an opt-in `lovverk/enrichment/legislative-links/`, or a
   separate sidecar.
2. **Lovtidend avd. I as a source:** `docs/decisions.md` §3 lists it as optional
   later. Accept it as the source of the law-decision edge, and confirm the NLOD
   basis for that dataset.
3. **Evidence retention:** Stortinget bytes are committed as test fixtures. Decide
   whether that is the lasting policy, and where Lovdata evidence lives, given that
   raw Lovdata XML stays out of every repository.
4. **Published schema:** contract v0 is still a research proposal. Decide whether to
   accept it and how to version it.
5. **Odelsting decisions:** extend the reader to `Besl. O.`, which contract v0 can
   already type, or restrict scope to `Lovvedtak`. Before 2013, most acts lack a
   `Lovvedtak` citation.
6. **Corrective re-sanction (#618):** approve the event model, and decide which
   source may assert a `corrects` relation.
7. **Digest policy:** decide whether repeat captures compare raw digests or parsed
   identities, after the cache behaviour is measured.
8. **`docs/decisions.md` §2 and §3:** reconcile the older exclusion of parliamentary
   enrichment, as ADR-0017 gate 5 requires.
9. **Next measurement:** run this reader over a declared sample, such as the 52
   instruments of #617, before any coverage claim. **Update 2026-11-02:** run, with
   label-free case discovery; see [the study of the 52](study-52-2026-11-02.md).
